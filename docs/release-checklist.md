### A-3. アプリ側の穴（私がやる）

**どれも「ベータで踏まれると印象が最悪」なもの。**

| # | 何が起きるか | いま | 直し方 |
|---|---|---|---|
| **1** | **画面が真っ白になった時の受け皿が無い** | `src/app/` に `error.tsx` も `not-found.tsx` も無い。描画で落ちると Next.js の既定の「Application error」だけが出る | 「**記録は消えていません**／開き直してください／直らない時はここから知らせてください」を出す。ベータでいちばん怖い見え方は、白い画面で記録が消えたと思われること |
| **2** | **全体の上限が、全員を同時に止める** | `DAILY_TURN_BUDGET` はアプリ全体で1日の合計。会員1人40回なので、**8人が使い切ると9人目以降は全員止まる**。出る文言は「今日はたくさん使われていて」で、まだ一度も使っていない人にも出る | 30人に配るなら 300 では足りない見込み。**まず数字を上げる**（A-1）。あわせて、止まった時の文言を「あなたの上限ではない」と分かる形にする |
| **3** | **`/admin` で、全体上限と個人の上限が見分けられない** | 「上限に当たった（会員）」は理由を合算している。全体上限で止まった分も、ここに混ざる | **判断を逆にする。**「会員が上限に当たった＝有料枠の出番」と読むはずが、実際は「全体の財布が尽きた」かもしれない。理由を分けて出す |
| **4** | **入口の離脱が測れない** | 数えているのは「コーチを選んだ人（signup）」から。**開いたのに選ばなかった人は残らない** | 9/30 に入口を初心者向けに作り替えたばかりで、効いたかどうかが分からない。「開いた」「最初の1通を送った」の2つを数える |

## C. ベータ中に見る数字（`/admin`）

**毎日見るのは上の3つだけでいい。**

| 見るもの | 何が分かるか | 危ない値 |
|---|---|---|
| **開いた → 選んだ → 送った** | 入口で何割が落ちているか。**いちばん直しがいがある所** | 選んだ人が半分を切る |
| **「良くない」の理由** | いちばんの改善材料 | — |
| **不具合** | 黙って壊れていないか | 1件でも出たら見る |
| 1回あたりの費用 | 値付けの根拠 | ¥6 を超える |
| 1通あたりの呼び出し回数 | 下げ余地（1に近いほど安い） | 3 を超える |
| 使い回し（%） | 指示文の並べ替えが効いたか | **0% なら効いていない** |
| 上限に当たった（会員） | お金を払ってでも使いたい人の数 | A-3 の 3 を直すまで、読み違える |
| 続いているか（直近7日） | 惰性ではなく本当に使われているか | 3日目に半分以下 |

## D. ベータのあと

**人が使い始めてから効いてくるもの。いま作っても確かめられない。**

| # | やること | なぜ後でいいか / なぜ要るか |
|---|---|---|
| **1** | **アカウントごと消せるようにする** | いまカルテから消せるのは記録だけ。**ログイン用のメールアドレスは手作業**（「お問い合わせください」）。30人なら回るが、増えると回らない。法的な請求対応としても、自分で消せるほうが強い |
| **2** | **預けた記録を持ち出せるようにする** | 出口があることは、預ける側の安心に直結する。「消せる」だけでなく「持って出られる」。開示請求の対応も楽になる |
| **3** | **無料枠と有料枠の付け替え** | いま ゲスト15 / 会員40 / 有料60。**実データを見てから決める。**「会員が何回で止まっているか」が出るまで、勘で決める意味がない |
| **4** | **止まった時の文言を、枠ごとに書き分ける** | 上限に当たる人が実際に出てから。誰が何で止まったかを見て書く |
| **5** | **オフラインで開いた時** | いまサービスワーカーは意図的にキャッシュを持っていない（古い画面が残るほうが困るため）。ただし**電車で開いて真っ白**は起きる。「つながっていません」だけでも出す |
| **6** | **複数端末での同期の確認** | ログインすれば同期する作りだが、実際に2台で使う人が出てから確かめる |
| **7** | **通知の頻度** | 毎朝で多すぎないか。押し売りになると一番早く嫌われる。**オフにした人の数**を見てから決める |
| **8** | **コンテキストキャッシュの本格導入** | まず「使い回し%」を見てから。並べ替えだけで足りているかもしれない |
| **9** | **コーチを変えた時の違和感** | 話し方だけ変わる作りだが、途中で変えた人がどう感じるかは使われないと分からない |

## E. 課金を始める時

### あなたがやること

**Stripe ダッシュボード**

1. 商品 →「RUNCOACH プレミアム」／継続／**¥1,480 月**／JPY → **価格ID**（`price_`）
2. 開発者 → Webhook → `https://legendary-running-coach.vercel.app/api/billing/webhook`
   - イベント：`checkout.session.completed` / `customer.subscription.created` / `.updated` / `.deleted`
   - → **署名シークレット**（`whsec_`）
3. 開発者 → APIキー → **シークレットキー**（`sk_`）

**Vercel の環境変数**

| 変数名 | 値 |
|---|---|
| `STRIPE_SECRET_KEY` | `sk_...` |
| `STRIPE_PRICE_ID` | `price_...` |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` |
| `LEGAL_ADDRESS` | 住所 |
| `LEGAL_PRICE_TEXT` | `月額 1,480円（税込）` |
| `LEGAL_MANAGER_NAME` | 責任者名（省略可） |

> **住所の記載は法律上必須。** 自宅を出したくなければバーチャルオフィス（月1,000円〜）。
> **4つが埋まるまで、申し込みは受け付けない**作りにしてある（`/commerce` が未完成なら 503）。
> テストモード（`sk_test_`）で一度通してから本番キーに替えること。

> **課金を入れる前に、副部長へ伝え直すこと。** 「収益化していない」は、
> 窓口が判断した前提のひとつ（`docs/beta-launch.md`）。
