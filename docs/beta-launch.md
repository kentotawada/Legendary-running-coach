## 1. オートチャージをオンにして、クレジットを ¥10,000 に

### なぜ

社内タイムラインは**同時に大勢が見る**ので、初日がいちばん混む。
残高が切れると**全員が止まる**。いちばん見られている日に
「利用上限に達しました」しか見られなかった人は、もう二度と開かない。

上限は `DAILY_TURN_BUDGET` で押さえてあるので、オートチャージを入れても
**青天井にはならない**（300回/日 × 約¥4.3 = 最大 約¥1,300/日）。

### 手順

1. **[aistudio.google.com](https://aistudio.google.com)** → 左メニューの **お支払い**（Billing）
2. プロジェクトが **Legend running coach** になっているか確認
3. **「クレジットを購入」** → **¥10,000**
   - 払い戻し不可・有効期限は購入日から1年。**買いすぎない**
4. **「自動リチャージを設定」**（オートチャージ: オフ の横）
   - **残高がいくらを下回ったら**：`¥2,000`
   - **いくら補充するか**：`¥5,000`
   - 保存

この設定なら、残高が¥2,000を切った時に¥5,000ずつ足される。
1日の最大支出は上限で押さえてあるので、月の最大は約¥39,000。
**そこまで行く前に予算アラートが鳴る。**

## 2. 予算アラートを ¥10,000 に

### 手順

1. **[console.cloud.google.com](https://console.cloud.google.com)**
2. 上部の検索バーに **「予算とアラート」**
3. **画面上部のプロジェクトが Legend running coach か確認**
4. 前に作った **¥1,000 の予算をクリックして編集**（新しく作らない。2つあると同じメールが2通来る）
5. 予算額を **`10000`**／種類：指定額／期間：月別／通貨：JPY
6. しきい値を4つに：

| しきい値 | 金額 | 種類 |
|---|---|---|
| 50% | ¥5,000 | 実績額 |
| 90% | ¥9,000 | 実績額 |
| 100% | ¥10,000 | 実績額 |
| **100%** | **¥10,000** | **予測額** ← これが一番早く気づける |

7. 保存

> **予算アラートは課金を止めない。**メールが届くだけ。
> 実際に止めるのは `DAILY_TURN_BUDGET`（アプリ側）と Google の割り当て。

### 件名：個人で作ったWebアプリを社内タイムラインで紹介してよいか（健康データの取り扱いを含む）

お疲れさまです。〇〇部の〇〇です。

業務外に個人で作成したWebアプリについて、社内タイムラインで紹介し、
希望者に任意で使ってもらうことを考えています。
健康に関する情報を扱うため、事前に確認させてください。

**1. 何か**

ランニングの練習記録をもとに助言をするWebアプリです（ブラウザで動きます）。
生成AIを使っており、Claude Code で開発しました。

**2. 運用の形**

- 業務時間外に個人で開発したものです
- 会社の資産・アカウント・ネットワークは一切使っていません
- サーバー費用は個人負担です
- **現時点で収益化しておらず、広告・課金はありません**

**3. 扱う情報**

利用者が入力した範囲で、以下を預かります。

- 練習の記録（距離・時間・心拍など）
- **体に関する情報（痛みの有無、体重、心拍など）**
- ログインに使うメールアドレス

保存先は Supabase（データセンターは東京）、通信は暗号化、
他の利用者の記録は読めない設定にしています。
利用規約・プライバシーポリシー・免責事項を用意しており、
初回に同意を得てから記録を預かる作りです。

**4. 確認したいこと**

- 社内タイムラインで紹介し、希望者に任意で使ってもらうことに問題はないか
- 同僚の健康に関する情報を、個人の環境で預かることについて留意点はあるか
- 投稿に含めるべき注記（「個人開発であり会社とは無関係」など）があれば教えてほしい
- その他、守るべき社内ルールがあれば教えてほしい

アプリのURL：https://legendary-running-coach.vercel.app
（規約類は画面下部と、/terms /privacy /disclaimer から読めます）

ご確認のほど、よろしくお願いいたします。

## 4. 社内タイムラインへの投稿

### A案：技術共有を前に出す（おすすめ）

> Claude Code でランニングコーチのアプリを作ってみた話
>
> 個人的な趣味で、走った記録を見て声をかけてくれるコーチのアプリを作りました。
> ほぼ全部 Claude Code に書いてもらっています。技術的に面白かったところを共有します。
>
> **■ 作ったもの**
> 走った内容をチャットで報告すると、コーチが返してくれるWebアプリです。
> 時計のスクリーンショットを投げると数値を読み取ってカルテに記録してくれます。
> コーチは8人いて、話し方が違います（中身と安全のルールは同じ）。
>
> **■ 技術的に面白かったところ**
>
> ・**安全のルールをプロンプトだけに頼らない**
> 　「痛みがある日は絶対に走らせない」を守らせたいのですが、
> 　プロンプトに書くだけだと守られない時があります。
> 　生成された文章をコード側で検査して、走るメニューが混ざっていたら
> 　書き直させる、という二段構えにしました。
>
> ・**数値をAIに書かせない**
> 　心拍ゾーンもペースも商品の価格も、AIには計算させずコードで出しています。
> 　AIが「それっぽい数字」を自信たっぷりに書くのがいちばん怖いので。
>
> ・**1通あたりのコストを4分の1にした話**
> 　最初は1通17円かかっていました。入力の半分が過去のやり取りの使い回しで、
> 　しかもその多くが機械同士のやり取りだったので、そこを削って約4円に。
> 　このへんは Claude Code と一緒に計測しながら詰めました。
>
> ・テスト1100件、全部 Claude Code が書いています
>
> **■ 使ってみたい方へ**
> 　https://legendary-running-coach.vercel.app
>
> 走る人向けです。特に「記録は取ってるけど続かない」「練習の内容がこれでいいのか
> 分からない」という方に合うと思います。スマホのブラウザで開けば使えます（登録不要で試せます）。
>
> ⚠️ **注意**
> ・個人で作ったもので、会社とは関係ありません
> ・**まだベータ版です。**動かないことがあります
> ・医療の代わりにはなりません。胸の痛みや息苦しさがある時は、すぐ運動をやめて受診してください
> ・痛みや体重などの記録を預かります。プライバシーポリシーをご確認のうえお使いください
>
> **変だと思ったら、返答の下の 👎 を押して理由を書いてください。**
