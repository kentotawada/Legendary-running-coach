# 費用と収益

RUNCOACH を事業として続けられる形にするための、実測と試算。

- 測った日：2026-09-29
- 測り方：`/admin` の実データ（1通ぶん）と、`src/lib/prompt.ts` / `src/lib/tools.ts` の実サイズ
- 円換算：1ドル = 150円（`src/lib/admin.ts` の `USD_TO_JPY`）

> **数字が古くなったら、ここを直すこと。** モデルの単価も、送っているトークン数も、
> コードを変えれば動く。古い数字を根拠に値段を決めるのが、いちばん危ない。

## 1. 実測：1通いくらか

道具（`set_today_plan`）を使う、ごく普通の1通：

| | トークン | 費用 | 割合 |
|---|---|---|---|
| 送った量（入力） | 52,170 | ¥15.65 | **93%** |
| 書いた量（出力） | 686 | ¥1.23 | 7% |
| **合計** | | **¥16.89** | |

単価は Gemini 3 Pro の `$2 / $12`（100万トークンあたり、入力 / 出力）。
`GEMINI_PRICE_PER_MTOK=2,12` の設定と、画面に出た ¥17 が一致することを確認済み。

**お金は「返事を書くこと」ではなく、「毎回ぜんぶ送り直していること」に消えている。**

## 2. なぜ 52,170 も送っているのか

実測したサイズ：

| 送っているもの | 文字数 | 性質 |
|---|---|---|
| コーチへの指示文（`prompt.ts`） | 11,544字 | **毎回まったく同じ** |
| 道具の説明（ツール定義14個） | 8,679字 | **毎回まったく同じ** |
| カルテ・会話の履歴 | 可変 | 毎回変わる |

指示文は、練習記録を30日ぶん入れても 10,311字 → 11,544字 にしか増えない。
つまり **約2万字（約1.3万トークン）は、誰が何を話しても必ず乗る固定費**。

さらに、道具を使う1通では**モデルを3回呼んでいる**。
道具を呼ぶたびに、その2万字を頭から送り直すため。

```
52,170 ÷ 3回 ≒ 17,400トークン/回
  ├ 固定の指示文＋道具の説明 …… 約13,000（75%）
  └ カルテ・会話 ………………… 約4,000（25%）
```

**同じ文章を、1通のために3回買っている。** これが ¥17 の正体。

> `/admin` の「1通あたり」に、この呼び出し回数が出る。
> **1 に近いほど安い。** 施策の効果は、まずこの数字で確かめる。

## 3. 30人のベータでいくらか

| 使われ方 | 回数/日 | Pro(¥17/回) | Flash(¥2.6/回) | Flash-lite(¥0.8/回) |
|---|---|---|---|---|
| 半分が1日2回 | 30 | ¥15,200/月 | ¥2,340 | ¥740 |
| 全員が1日2回 | 60 | **¥30,400/月** | ¥4,680 | ¥1,480 |
| 全員が1日4回 | 120 | **¥60,800/月** | ¥9,360 | ¥2,950 |
| 上限まで（旧設定300回） | 300 | **¥152,000/月** | ¥23,400 | ¥7,380 |

Pro のままでは、Google に設定した ¥1,000 の予算アラートが**ベータ初日〜2日目に鳴る**。

> Flash / Flash-lite の単価は一般的な水準での試算。
> 正確な数字は Google の料金表で確かめて `GEMINI_PRICE_PER_MTOK` に入れる。

## 4. 課金しても黒字になるか

会員1人が**1日4回**（月120回）使うとして：

| 月額 | Web決済後の手取り | 原価 ¥17/回 | 原価 ¥2.6/回 | 原価 ¥0.8/回 |
|---|---|---|---|---|
| ¥480 | ¥463 | **−¥1,564** | +¥151 | +¥364 |
| ¥980 | ¥945 | **−¥1,082** | +¥633 | +¥846 |
| ¥1,480 | ¥1,427 | **−¥600** | +¥1,115 | +¥1,328 |
| ¥1,980 | ¥1,909 | **−¥118** | +¥1,597 | +¥1,810 |

**Pro のままでは、月額1,980円にしてもまだ赤字。**
値段でどうにかする話ではなく、単価を下げる話。

決済手段：アプリストア経由は手数料15%（小規模事業者プログラム）、Stripe は3.6%。
PWA なので、まずは Web決済で始めるほうが手取りが約100円多い。

## 5. リリース後の収益

前提：月額¥980・Web決済・登録者の20%が毎日利用・無料2回/日・有料4回/日。
無料の人は安いモデル（¥0.8/回）、有料の人は良いモデル（¥2.6/回）。

| 登録者 | 転換率 | 有料 | 月商 | 原価＋インフラ | 粗利/月 | 粗利/年 |
|---|---|---|---|---|---|---|
| 100 | 5% | 5人 | ¥4,900 | ¥2,495 | ¥2,200 | ¥27万 |
| 1,000 | 5% | 50人 | ¥49,000 | ¥31,698 | ¥15,500 | ¥186万 |
| 1,000 | 10% | 100人 | ¥98,000 | ¥46,806 | ¥47,700 | ¥572万 |
| 5,000 | 10% | 500人 | ¥490,000 | ¥207,030 | ¥265,000 | ¥3,184万 |
| 10,000 | 7% | 700人 | ¥686,000 | ¥316,662 | ¥345,000 | ¥4,136万 |
| 30,000 | 7% | 2,100人 | ¥2,058,000 | ¥936,486 | ¥1,047,000 | ¥1.26億 |

**効くのは転換率。** 1,000人登録で5%なら月1.5万円、10%なら月4.8万円。同じ登録者数で3倍違う。

**無料の人のコストが最大の落とし穴。** 全員を良いモデルで回すと、
登録1,000人・転換5%では**月4,754円の赤字**になる。
無料の人にどのモデルを使わせるかが、黒字か赤字かを決める。

### 月額以外の柱

- **楽天アフィリエイト**（実装済み）：シューズ1足 ¥20,000 × 料率2〜4% ＝ 1件 ¥400〜800。
  「そろそろミッドソールが終わる」と言える状態で薦められるのは強い。ただし原価を埋める規模にはならない
- **大会前の単発課金**：「フルマラソン12週間プラン ¥3,000」のような売り切り。
  月額に抵抗がある層に届く。ランナーは大会前だけ財布が緩む

## 6. 単価の下げ方（効く順）

| # | やること | 効果 | 状態 |
|---|---|---|---|
| ① | ふだんの会話を Flash に落とす | ¥17 → ¥2.6（6.5分の1） | **済**（2026-09-29） |
| ② | 道具の説明を、必要な時だけ送る | 毎回 −3,000〜4,000トークン | 未 |
| ③ | モデルを呼ぶ回数を減らす | 3回→2回 で ¥17 → ¥11.7 | 未 |
| ④ | コンテキストキャッシュ | 固定1.3万トークンぶん | 未（①〜③の後に測る） |
| ⑤ | 無料枠を絞る | 会員40回/日は1人で月2万円 | 未 |
| ⑥ | `DAILY_TURN_BUDGET` を下げる | 300 → 120 | **済**（2026-09-29） |

### ① でやったこと

- ふだんの会話：`gemini-3-flash-preview`（`GEMINI_MODEL`）
- 画像が付いたターンだけ：`gemini-3-pro-preview`（`GEMINI_MODEL_VISION`）

**分けているのは頼みごとの重さであって、人ではない。**
時計の画面やフォームの写真の読み取りは、取り違えると助言そのものが狂う。
ここだけは安いほうに倒さない。

**無料の人と会員でモデルを変えてはいない。** 変えると、無料の人が
「このアプリ、たいしたことない」と判断して離れる。まず良さを体験してもらう。
（→ 7章）

### ⑥ でやったこと

`DEFAULT_DAILY_BUDGET` を 300 → **120**（30人 × 1日4回）。

**Vercel の環境変数 `DAILY_TURN_BUDGET` はコードより優先される。**
そちらも 120 に直さないと、この変更は効かない。

| 上限 | Flash(¥2.6/回) | Pro に戻した場合(¥17/回) |
|---|---|---|
| 60 | ¥156/日・¥4,680/月 | ¥1,013/日 |
| **120** | **¥312/日・¥9,360/月** | ¥2,027/日 |
| 300 | ¥780/日・¥23,400/月 | ¥5,100/日 |

## 7. 無料と有料の分け方

**モデルの質では分けない。** 無料の人が「イマイチ」と感じて離れると、
そもそも有料に上がる母数が無くなる。一番良いコーチを、まず全員に体験してもらう。

分けるなら、**回数と機能**で分ける。

| | 無料 | 有料 |
|---|---|---|
| コーチの質（モデル） | 同じ | 同じ |
| 1日に話せる回数 | 3〜5回 | 40回 |
| 画像の読み取り | 同じ | 同じ |
| 過去の記録 | 直近30日 | すべて |
| 大会用の計画・チェックリスト | — | あり |
| Strava の自動取り込み | 手動 | 自動 |

「回数で止まる」は、**満足した人にだけ効く壁**。
つまらないと思った人は回数に届かないので、そもそも壁にぶつからない。
`/admin` の「上限に当たった（会員）」が増えてきたら、有料枠を出す頃合い。

現在の設定（`src/lib/quota.ts`）：ゲスト 15回/日、会員 40回/日。
会員40回は、Pro 換算で**1人あたり月2万円**まで使える幅。
有料枠を作るタイミングで、無料側を 3〜5回/日 に絞る。

## 9. 運用：使いすぎを止める3段構え

**止まる仕組みと、気づく仕組みは別のもの。** 混ぜると、止まっているつもりで止まっていない。

| 段 | 何か | 本当に止まるか | 状態 |
|---|---|---|---|
| 1段目 | アプリの1日上限（`DAILY_TURN_BUDGET`） | **止まる** | 実装済み |
| 2段目 | Google 側の API 割り当て（クォータ） | **止まる** | 要設定 |
| 3段目 | 予算アラート | **止まらない**（メールが届くだけ） | 要設定 |

1段目が主役。2段目は、1段目の数え方が壊れた時の最後の砦。
3段目は、1〜2段目をすり抜けた時に**人間が気づく**ためのもの。

> 予算アラートは上限ではない。¥5,000 を設定しても、¥50,000 使えば ¥50,000 請求される。

### 1段目：アプリの1日上限

Vercel の環境変数 `DAILY_TURN_BUDGET`。既定は 120（`src/lib/quota.ts`）。

**環境変数はコードの既定より優先される。** 変えたらリデプロイが要る。
モデル名も同じ（`GEMINI_MODEL` / `GEMINI_MODEL_VISION`）。古い値が残っていると、
切り替えたつもりが効かない。**いま何で動いているかは `/api/health` の
`model` と `visionModel`、またはカルテの一番下で確かめる。**

### 2段目：Google 側の API 割り当て（クォータ）

Google Cloud Console → 検索バーに「**割り当てとシステム上限**」（`IAM と管理`）。
「割り当て増加リクエスト」は上限を**増やす**申請ページなので別物。

**Gemini の API キーを作ったプロジェクトを選んでいること。** 別のプロジェクトに
かけても、Gemini の請求は捕まらない。

絞り方（2026-09 時点の画面）：

1. フィルタ → プロパティ **サービス** → **Gemini API**
2. キーワードに `generate_requests` と入れる
   （`create_voice_*` は音声合成。このアプリは使っていないので全部無視）
3. 目的の割り当て：

| 割り当ての ID | 何か |
|---|---|
| `generativelanguage.googleapis.com/generate_requests_per_model_per_day` | **1日あたり。これが実際の上限** |
| `generativelanguage.googleapis.com/generate_requests_per_model` | 1分あたり。暴走の勢いは止まるが、1日の総額は止まらない |

行はモデルごとに分かれている。設定した値（2026-09-29）：

| モデル | 変更前 | 変更後 | 最悪額（変更後） |
|---|---|---|---|
| `gemini-3-flash` | 10,000/日 | **450** | 約¥10,600/月 |
| `gemini-3-pro` | 250/日 | **60** | 約¥9,400/月 |

450 は、アプリ上限120通 × 1通3回 = 360 に余裕を足した数。
Pro の 60 は、画像つきの会話20回ぶん。

**Pro をきつく絞っても壊れない。** 上限に当たると Flash へ自動で退避して
読み取りを続ける（`candidateModels` / `tests/gemini.test.ts`）。
読み取りの精度は落ちるが、エラーにはならない。

**Flash のほうは、絞りすぎるとふつうに使っている人が弾かれる。**
両方の上限に当たると `Gemini API の利用上限に達しました` と画面に出て、
アプリは落ちずに止まる（`src/lib/gemini.ts`）。落ちないが、その人はもう話せない。

**1日あたりの割り当てが無いモデルもある。** その場合、1分あたりだけでは
1日の総額は止まらない（60/分 × 1440分 = 86,400件）。1段目が主役なのはそのため。

### 3段目：予算アラート

Google Cloud Console → 検索バーに「予算とアラート」。
**既存の予算を編集する。**新しく作ると、同じ内容のメールが2通来る。

- 予算額：**¥5,000**／種類：指定額／期間：月別／通貨：JPY
- しきい値：

| しきい値 | 金額 | 種類 |
|---|---|---|
| 50% | ¥2,500 | 実績額 |
| 90% | ¥4,500 | 実績額 |
| 100% | ¥5,000 | 実績額 |
| **100%** | **¥5,000** | **予測額**（← これが一番早く気づける） |

「予測額」は「このペースだと月末に超える」で鳴る。実績額は使ってしまった後に届く。

**¥5,000 の根拠**：想定どおりのベータ（30人・半分が1日2〜3回）で月約¥3,100。
その1.6倍で鳴る位置＝「何かおかしい」。
1段目の上限まで毎日使われた最悪でも月約¥9,400 なので、
「本当の異常だけ鳴らしたい」なら ¥10,000 にする。
最初のベータは、早めに鳴る ¥5,000 のほうがいい。

### やらないこと

予算超過で自動的に請求先アカウントを切り離す仕組み（Cloud Function）は**使わない**。
請求データの反映に数時間の遅れがあるので「気づいた時には手遅れ、かつ過剰に止まる」
という最悪の組み合わせになる。しかもプロジェクト全体が止まり、復旧に手間がかかる。
1段目・2段目のほうが速く、確実で、アプリも壊れない。
